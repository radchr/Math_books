# Feynman-Manim-Composer (Math_books 9:16 Edition)

Педагогічний і режисерський місток між **ідеєю з книги / науки / баскетболу** та **модульними сценами Manim** у `Math_books`.
Перетворює будь-яку тему з математики, фізики, хімії, біології чи спортивної статистики на чітку двоколонкову розкадровку (`9:16`, режим `voiceover` 55–70 с або `music_only` 20–45 с) для цільової аудиторії (типово 12+ років або вказаний `audience_age`) **до** збереження в банк сценаріїв і запуску рендеру.

---

## Чому цей підхід працює краще за звичайний сценарій

1. **Без «лекції з крейдою»:** формула з'являється *лише після того*, як глядач уже побачив фізичну чи ігрову інтуїцію.
2. **Без «голлівудської води»:** емоційний хук (перші 3–5 с) завжди веде до точної математичної моделі, а не до порожнього клікбейту.
3. **Сходження за Брунером (CRA) + P-O-E-M:**
   - **Predict (Хук):** змусь глядача зробити інтуїтивний прогноз до відповіді.
   - **Enactive → Iconic (Дія → Схема):** м'яч, майданчик, сітка, дерево, стовпчики.
   - **Symbolic (Формула):** коротке рівняння як запис уже побаченого.
   - **Limitations (Де модель ламається):** чесна межа аналогії — напряму лягає в `content_reviews/<topic>.json`.
   - **Mission (Челендж):** 10-секундна задача-перевірка наприкінці.

## Канонічна 5-сценна структура для `Math_books` (55–70 с, 130–170 слів)

| Сцена | ID | Час | Педагогічна роль | Голос (TTS) | Екран (Manim 9:16) |
|---|---|---|---|---|---|
| 1 | `01_hook` | 8–14 с | **Predict / Парадокс** | Інтрига з NBA або дворового баскетболу; питання-вибір. Без формул. | Табло, майданчик (`make_half_court`), м'яч (`make_basketball`), бейдж. |
| 2 | `02_setup` | 12–15 с | **Enactive / Умови моделі** | Прості точні числа, явні припущення (наприклад, незалежні кидки). | Картки умов (`make_stat_card`), схема ситуації на майданчику. |
| 3 | `03_twist` | 11–16 с | **Iconic / Несподіваний поворот** | Де інтуїція помиляється; перший точний розрахунок. | Сітка, дерево або стовпчики; `TransformMatchingTex` для підстановки чисел. |
| 4 | `04_proof` | 12–16 с | **Symbolic + Межа моделі** | Короткий висновок + чесне застереження, де модель спрощує реальну гру. | Порівняння планів, підсвітка переможця, компактний висновок. |
| 5 | `05_challenge` | 9–15 с | **Mission / 10-сек челендж** | Нова міні-задача з паузою на роздуми і миттєвою перевіркою. | Питання → пауза → поява відповіді через `self.word_timestamp(...)`. |

## Формат двоколонкової розкадровки (для погодження з користувачем)

```markdown
### Сцена 1: `01_hook` (~10 с)
* **Педагогічна мета:** Запустити інтуїтивний прогноз глядача.
* **Точна математика / модель:** `direct_prob = Fraction(3, 10)` vs `chain = (7/10, 1/2, 7/10)`.

| Час | Закадровий голос (TTS-ready) | Дія на екрані (Manim 9:16) |
|---|---|---|
| 0:00–0:04 | «Десять секунд до сирени! Твоя команда програє три очки...» | `make_scoreboard`, `make_half_court`, `FadeIn` бейджа `make_badge`. |
| 0:04–0:10 | «Бити складну трійку одразу чи розіграти комбінацію?» | Дві стрілки планів А і Б; підсвітка активної траєкторії. |
```

## Правила когнітивної ясності та технічні обмеження `Math_books`

- **Орієнтир когнітивного навантаження:** одночасно пояснюй приблизно **3–4 змістові групи**, а не лімітуй кількість `Mobject`. Сітка зі ста клітинок може бути однією групою. Це робоча рекомендація, а не універсальний закон.
- **Проста мова озвучки (Separate meaning from notation):**
  - Екран (`MathTex`) показує формулу, а голос пояснює **ідею** людською мовою (без механічного читання символів і без LaTeX/цифр у тексті TTS).
  - Усі числа, дроби й відсотки — словами; в українській — природні звороти (*«половина»*, *«три з десяти»*); у російській — обов'язково `ё`.
  - Не вставляй теги на кшталт `[pause 0.5s]` у фінальний масив `SCENES` для TTS (тримай паузи лише в нотатках розкадровки).
- **Сумісність із нашим Manim-пайплайном:**
  - Шрифт тексту: `FONT` (`DejaVu Sans` із `video_ui.py`), **ніколи** не передавай кирилицю в `MathTex()`.
  - Полотно: `1080×1920`, безпечна зона `|x| <= 4.35`, `y ∈ [-6.15, +7.45]`, ширина тексту `≤ 7.6`; декларативні сцени додатково проходять автоматичну перевірку перетинів `require_no_mobject_overlaps()` і стрес-тест верстки `tests/test_visual_layout_stress.py`.
  - Числа озвучки й екрана мають спиратися на спільну перевірювану модель; для раціональної арифметики використовуй `fractions.Fraction`, для рівнянь, алгебри й фізичних формул — `SymPy`-чеки (`sympy_identity`, `sympy_solve`, `sympy_formula_eval`) із явними припущеннями домену та одиницями.
  - Ніякого `self.add_sound()`; аудіо зводиться окремо через `math-books build <topic>`.
- **Модульні візуальні блоки та теми (`src/math_books/visual_blocks/`):**
  - Перед тим як проєктувати кастомний Manim-код, розклади кожну сцену на наявні перевикористовувані блоки: `text_card`, `hook_choice`, `compare_bars`, `step_chain`, `challenge_card`, `image_stage` (SVG/PNG-схеми з `assets/diagrams/`), або доменні паки `packs/basketball/{half_court_diagram,scoreboard_duel}`.
  - Обери тему оформлення (`neutral_dark`, `science_lab`, `basketball_dark`).
- **Режим `music_only` (фонова музика + написи без озвучки):**
  - Коротший темп: 20–45 с (3–5 сцен), явні `duration_s` і часові `cues`, ультрастислі титри (до 6–10 слів на картку) та опора на наочну схему (`image_stage` / `visual_blocks`).
  - Підбирай або додавай трек із бази `assets/music/` (`math-books music list | generate | import`).
  - Педагогічний скелет (Predict → Observe → Explain → Mission) і явні `assumptions`/`limitations` для `content_review.py` лишаються обов'язковими.
- **Перехід до реалізації:** після затвердження розкадровки користувачем збережи запис у банк сценаріїв (`content/bank/<id>.json` → `uv run math-books bank promote <id>`) і переходь до скілу `stem-basketball-video` (аудит `anti-slop-review` → `content_reviews/<lang>/<topic>.json` → TTS або `music_only` → опціонально швидкий `build --draft` → `build` → `verify --frames`).

Для нових тримовних уроків розкадровка має містити `uk`, `ru`, `en` narration (або наекранні титри для `music_only`) та підписи за стабільними scene ID. Формули лишаються спільними. Формат, мовні шляхи й `--lang` описані в `docs/three-language-videos.md`; старі Python-сцени не перекладаються автоматично. Нові декларативні уроки використовують явні `cues` (`cue_timeline.py`), а legacy `VerticalShortScene.word_timestamp` споживає лише перевірений `timing_snapshot` із точним Unicode-зіставленням, а не довільний JSON за часом зміни.
