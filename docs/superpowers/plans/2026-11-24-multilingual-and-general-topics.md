# Багатомовність і нові теми: план майбутніх робіт

**Статус:** backlog; реалізацію не розпочато.
**Дата:** 2026-11-24.
**Мета:** додати українську й англійську озвучку та написи, а потім розширити
проєкт для освітніх відео поза математикою і баскетболом.
**Основа:** обговорення можливостей проєкту; перед реалізацією кожного етапу
уточнити його дизайн і скласти детальний implementation plan.
**Стек:** наявні Python/uv, Manim, Gemini TTS, локальний ASR, ffmpeg та unittest.

## Поточний стан

- CLI працює з фіксованим `VIDEO_TOPICS` у `src/math_books/video_builder.py`.
- Озвучка задана російськими `SCENES` у `generate_*_tts.py`.
- Екранні написи розміщені безпосередньо в Python-коді сцен.
- ASR використовує `language="ru"`, а порівняння мовлення — російську морфологію
  та правила числівників у `spoken_text.py`.
- Редакційний контроль розрахований на науково-математичні твердження й аудиторію
  віком 12 років.
- Спільний механізм рендерингу та монтажу можна використати для інших тем,
  але автоматичної генерації довільної сцени з текстового запиту зараз немає.

## Порядок і межі

Пропонований порядок: A → B → C. Це рекомендація для майбутньої реалізації.

1. **A — багатомовність:** один наявний ролик українською, англійською та російською.
2. **B — нові теми:** декларативний опис уроку й набір перевикористовуваних сцен.
3. **C — генерація із запиту:** створення чернетки уроку з перевіркою перед виробництвом.

Альтернатива з копіюванням Python-сцен для кожної мови простіша на старті, але
ускладнює синхронізацію перекладів. Повністю автоматичне створення довільного
Manim-коду одразу збільшує обсяг і ризики. Рекомендовано спочатку локалізовані
дані, потім обмежений набір шаблонів.

Озвучка й написи одного експорту спочатку мають одну мову. Незалежний вибір мови
аудіо та субтитрів, дубляж зовнішніх відео й автоматична публікація — поза першим
етапом. Оцифрування книжок зберігає окремий процес.

- [ ] Явно визначити цільову тривалість пілота: нинішній `buzzer` близько 77 с,

```bash

uv run math-books tts buzzer --lang uk
uv run math-books build buzzer --lang uk
uv run math-books verify buzzer --lang uk
uv run math-books build buzzer --lang en
```

## C. Створення чернетки уроку з текстового запиту

**Залежність:** завершений етап B; окремий дизайн перед реалізацією.

- [ ] Визначити вхід: тема, аудиторія, мова, навчальна мета та тривалість.
- [ ] Генерувати структуровану чернетку сценарію, джерела й вибір доступних
  шаблонів; перевіряти її схемою уроку.
- [ ] Для невідомої теми, відсутніх доказів або непідтримуваної візуалізації
  повертати конкретні невирішені питання, а не заявляти готовність відео.
- [ ] Створювати лише pending-досьє: генератор не схвалює власний сценарій
  автоматично. Зберегти чинний редакційний gate перед TTS і рендерингом.
- [ ] Перевірити кілька тем різних предметів, помилкові факти, суперечливі
  джерела й недоступність зовнішнього провайдера.

**Готово, коли:** запит створює придатну для перевірки чернетку, а після
фактичного review — відео через той самий перевірюваний конвеєр.
«Будь-яка тема» означає розширюваний набір предметів і шаблонів, а не гарантію
автоматичного створення довільного відеоряду.

## Загальні обмеження й перевірка

- Усі Python/Manim-команди виконувати через `uv run`.
- Зберегти silent render + окремий WAV + ffmpeg mux; не використовувати
  `Scene.add_sound()` для виробничої синхронізації.
- Не передавати кирилицю до `MathTex`; локалізовані написи створювати через `Text`.
- Зберегти 1080×1920, 30 fps і візуальну перевірку кадрів кожної мови.
- Не обходити review/ASR gates і не переносити схвалення між зміненими версіями.
- Реальні TTS-проби відокремити від офлайн-тестів; не зберігати ключі в репозиторії.
- Перед завершенням кожного етапу запускати unittest, Ruff і перевірку lock-файлу;
  для виробничого пілота додатково запускати `verify-audio` та `verify`.

```bash
uv run python -m unittest discover -s tests -v
uv run ruff check src tests
uv run ruff format --check src tests
uv lock --check
```
