# Три мови для майбутніх відео

Майбутні уроки підтримують `uk`, `ru`, `en`: озвучку, екранні написи, локальний
ASR, перевірку тексту, окремі review й артефакти. Існуючі сім Python-сцен
залишаються російськими; їхні сценарії, схвалення, аудіо та відео не мігруються.

## Формат нового уроку

Створіть `content/lessons/<topic>.json` за прикладом
[`language_demo.json`](../content/lessons/language_demo.json). Назва файлу й
`topic` мають збігатися; допустимі малі латинські літери, цифри та підкреслення.
Не використовуйте назви старих тем.

Кожна сцена має стабільний `id`, необов'язкову спільну `formula` та повний набір
`translations.uk`, `.ru`, `.en`, кожен із `text` (озвучка), `title` і `body`
(екран). Відсутні/порожні переклади блокують усі мовні версії, а не підміняються
російською. Формула використовує обмежену математичну LaTeX-нотацію без кирилиці
та команд читання файлів.

Нові уроки автоматично з'являються у CLI без редагування `VIDEO_TOPICS`.
Спільна `LocalizedLessonScene` створює картки з перекладеними заголовками,
поясненням і формулою. Вона не перекладає довільний старий Manim-код автоматично.
Для складніших анімацій потрібен окремий розроблений мовний шаблон сцени.

## Поява елементів за словами озвучки

Необов'язкові `cues` задають момент появи `title`, `body` або `formula`.
Приклад із `language_demo.json` приховує формулу до слова «Разом» / «равно» /
«equals»:

```json
"cues": [{
  "id": "answer_reveal",
  "target": "formula",
  "anchor": "start",
  "occurrence": 1,
  "phrases": {"uk": "Разом", "ru": "равно", "en": "equals"}
}]
```

`anchor` — `start` або `end` фрази, `occurrence` — номер її повторення від 1.
Кожен цільовий елемент має щонайбільше один маркер. Фрази перевіряються в усіх
трьох сценаріях; маркер не може збігтися з частиною складеного числівника.
Якщо відповідного слова немає у перевірених ASR-таймінгах, збірка зупиняється.

Рендер використовує заморожені ASR-таймінги й розклад подій. Час округлюється
до найближчого кадру 30 fps від **накопиченого** аудіочасу, включно з паузами
400 мс між сценами. Окреме округлення тривалості кожної сцени не накопичує
дрейф. Журнал фактичних локальних і глобальних кадрів перевіряється з допуском
один кадр та зберігається в `.build.json`; зміна таймінгів інвалідує кеш рендера.
Це точність відносно ASR-оцінки слова: сам Whisper може помилятися в межах слова.

## Акустичний контроль нових кліпів

Нові мовні уроки вимагають `quality_check: true` у маніфесті. Під час генерації,
перевірки кешу й читання таймінгів PCM перевіряється повторно; збережене
`ok: true` не замінює вимірювання.

- `pass`: текстовий і акустичний контроль пройдені.
- `fail`: пошкоджений/порожній/непідтримуваний WAV, повна тиша або щонайменше
  1% семплів біля межі PCM16 (`abs(sample) >= 32760`).
- `needs_review`: розбіжність ASR із текстом, RMS нижче −35 dBFS, крайова пауза
  понад 0,75 с, внутрішня понад 2 с або значне DC-зміщення.

Енергія вимірюється у вікнах 20 мс з порогом −50 dBFS. Це енергетичний аналіз,
а не нейромережевий VAD; RMS не є LUFS, а частка граничних семплів — true peak.
Вимірювання не сертифікують наголоси, природність чи відсутність усіх дефектів.
Пороги й код аналізатора входять до ідентичності QA-політики.

`needs_review` блокує пакет і зупиняє автоматичні платні повтори. Кандидат WAV
і повний звіт зберігаються без перезапису в `audio/review_required/`; шляхи є
в повідомленні помилки. Попередній виробничий маніфест зберігається. Це докази
для прослуховування, а не схвалення або спосіб обійти QA. Виправте текст/аудіо,
застосуйте `--trim-edges` для крайових пауз або дослідіть помилку розпізнавання
і повторіть перевірку. Помилки інфраструктури ASR відділені від дефектів TTS.

Edge TTS зберігає сирі `WordBoundary` у допоміжному sidecar, прив'язаному до
хешів MP3/WAV, із точним зсувом обрізання в семплах. Обов'язковий відсутній або
змінений sidecar блокує кеш. Ці таймінги залишаються **допоміжними**: невідомий
зсув MP3-декодера не дозволяє вважати їх точним годинником фінального WAV.
Фінальні маркери поки використовують незалежний ASR.

WhisperX / stable-ts, нейромережевий VAD і MOS-оцінки поки не додані в залежності:
для них потрібен окремий порівняльний набір реальної української, російської та
англійської озвучки. Висока MOS-оцінка сама не доводить правильність чисел чи змісту.

## Команди

```bash
uv run math-books list --lang uk
uv run math-books review language_demo --lang uk --init
uv run math-books review language_demo --lang uk
# Після фактичного наукового й педагогічного схвалення поточного досьє:
uv run math-books tts language_demo --lang uk --trim-edges
uv run math-books build language_demo --lang uk
uv run math-books verify-audio language_demo --lang uk
uv run math-books verify language_demo --lang uk --frames
```

Аналогічно для `--lang ru` та `--lang en`. Типова мова старих команд — `ru`.
Українська типово використовує український TTS-ланцюжок; російська й англійська —
Gemini. Для української можна явно обрати `--provider gemini`; для інших мов
`--provider uk` заборонений. `--voice` задає Gemini-голос, `--uk-profile` — профіль
українського ланцюжка.

Тестовий `language_demo` не має виробничого схвалення. Не записуйте `approved`
заради запуску прикладу: спершу проведіть справжнє review. Синтетичні схвалення
в unittest існують тільки в тимчасових каталогах.

## Ізоляція та перевірки

- Нові експорти: `videos/video_<topic>/<lang>/`, включно з аудіо, QA й Manim-кешем.
- Нові досьє: `content_reviews/<lang>/<topic>.json`; кожна мова схвалюється окремо.
- Досьє прив'язане до narration, заголовків, тексту та формул. Зміна напису
  інвалідує схвалення, навіть якщо голосовий текст не змінився.
- Кожен маніфест містить одну мову. ASR використовує відповідний мовний код;
  receipts прив'язані до мови, WAV, тексту й поточної політики нормалізації.
- Український кеш враховує профіль, голоси, параметри й локальні файли моделей.
  Часткове використання кешу не дозволяє змінити голос посеред ролика.
- У нових Gemini-пакетах модель закріплюється після першого схваленого кліпу.
  Тимчасові помилки повторюються на тій самій моделі; збій ASR не запускає
  платний fallback. Попередній опублікований пакет зберігається при помилці.
- Рендер споживає один незмінний snapshot перевірених таймінгів. Зміна слова,
  підпису чи таймінгу інвалідує повторне використання старого рендера.

Український та англійський QA порівнюють нормалізовані токени консервативно.
Підтримуються числівники, точні дроби, десяткові числа, відсотки, заперечення
й математичні операції. `2/3` — дріб; `2 / 3` — явно записана операція ділення.
Непідтримувані граматичні конструкції або помилки ASR можуть спричинити відмову;
не обходьте gate й не послаблюйте правила, щоб приховати зміну значення.

Для української типова модель Whisper — `small`, для російської й англійської —
`base`. Це окремий вибір від TTS: у живій пробі `base` неправильно розпізнавала
чіткі українські числівники. Перший запуск `small` потребує завантаження моделі.
Модель можна задати через `MATH_BOOKS_ASR_MODEL_UK`, `_RU`, `_EN` або загальну
`MATH_BOOKS_ASR_MODEL`; дозволені `tiny`, `base`, `small`, `medium`, `large-v3`.
Англомовні варіанти `tiny.en`, `base.en`, `small.en`, `medium.en` дозволені лише
для `en`. Зміна моделі інвалідує QA receipt; шляхи/URL замість ID заборонені.

Примусова мова Whisper не сертифікує акустично мову мовця. ASR також не
сертифікує наголоси й дикцію; потрібне прослуховування.

## Перевірка реалізації

```bash
uv run python -m unittest discover -s tests -v
uv run ruff check src tests
uv run ruff format --check src tests
uv run ty check
uv lock --check
```

Офлайн-регресії перевіряють реальні мовні порівняння, receipts, review, мовні
шляхи, fingerprints і атомарну публікацію. Межі зовнішнього TTS та рендера
позначені заглушками; це не видається за перевірку живого провайдера.

Окремо виконуються короткі smoke-проби справжнього TTS/Whisper та реальний
Manim → ffmpeg/ffprobe для трьох мов із переглядом кадрів. Такі тестові медіа
зберігаються в `/tmp/math-books-language-smoke/`, окремо від старих роликів;
вони не є редакційно схваленими виробничими експортами.
