# Виправлення за код-рев'ю: 2026-11-25

## Що змінилося

- Gemini отримує ключ через `x-goog-api-key`. Повідомлення HTTP, тіло відповіді
  й помилки повторів очищуються від буквального та URL-кодованого ключа.
- `math-books list` — лише інвентаризація: без Whisper, ffprobe, ffmpeg,
  хешування WAV/MP4 і запису QA. Читач перевіряє лише вже наявний lock-файл;
  зайнята тема отримує `busy`. Відсутній каталог/lock не створюється.
- `unverified` означає, що файли є, але їхня відповідність не перевірена.
  `stale` означає помилку доступних метаданих, `blocked` — редакційний блокер,
  `missing` — відсутність файлів. Навіть справний старий експорт у швидкому
  списку не отримує `verified` або `ready: true`. Повні перевірки залишаються
  в `verify-audio` і `verify`.
- `.render.json` і `.events.json` публікуються через тимчасовий файл у тому
  самому каталозі, flush/fsync і replace; невдалий запис зберігає старий JSON.
- Legacy-маркери читають тільки поточну перевірену QA-квитанцію через
  `timing_snapshot`, без ASR або записів. Зіставлення точне й підтримує
  українські літери; `да` більше не збігається з `дальше`. Для необов'язкового
  legacy-маркера залишається явно заданий fallback. Декларативні cues, як і
  раніше, блокують збірку при відсутньому обов'язковому маркері.
- UK/EN QA має окремі набори захищених слів: числа, операції, одиниці,
  заперечення, умови та наукові уточнення. Однолітерні змінні захищені;
  довільні заміни дволітерних слів більше не мають окремого допуску для UK/EN.
  Невеликі орфографічні розбіжності незахищених слів можуть пройти з warning
  за попередніми обмеженнями WER/схожості. Словники не доводять семантичну
  еквівалентність довільного наукового тексту; потрібен перегляд звіту й слухання.
- Єдиний валідатор перевіряє provenance аудіоманіфестів у build і verify-audio.
  `media_io.py`, `pipeline_errors.py` та `topics.py` відокремлюють WAV/locking,
  винятки й реєстр тем від оркестрації. Імпорт пакета більше не завантажує CLI.
- `pydub` та `img2pdf` вилучені з прямих залежностей. **pydub залишається
  транзитивною залежністю Manim**, тому це не його повне вилучення з оточення.
  Piper залишається необов'язковим зовнішнім провайдером: потрібні встановлений
  пакет із `piper.voice` і відповідні локальні модель/config із voice_profiles.toml.
  Базове встановлення не обіцяє доступності цього рівня fallback.

## Стан історичних схвалень

Історичні досьє, WAV, MP4 і їхні sidecar-файли не оновлювалися автоматично.
Зміна `video_ui.py` робить прив'язані до старого хешу досьє застарілими;
нормалізатор і QA-код змінюють QA-політику. Це очікуване блокування, а не
доказ пошкодження старого відео. Хеш-інвалідація політики збережена; перехід
на суто ручний номер версії не виконувався.

Для `buzzer` підготовлено **неактивну, несхвалену** пропозицію
[`content_reviews/proposals/buzzer.json`](../content_reviews/proposals/buzzer.json).
Вона містить точні `independent_chain` перевірки:

- `7/10 × 1/2 × 7/10 = 49/200 < 3/10`;
- `(4/5)³ = 64/125 > 1/2`.

Старі рішення рецензентів у пропозицію не перенесені. Підтримка check працює
з довільною непорожньою послідовністю до 100 ймовірностей у `[0,1]`, включно
з рівністю шансів. Незалежність і значення вхідних ймовірностей залишаються
передумовами для редакційної перевірки.

Щоби знову отримати актуально верифікований **виробничий** `buzzer`, потрібні:

1. Фактичне повторне наукове й педагогічне рев'ю нового досьє та його хешу;
   архівування попереднього й активація нового досьє лише після такого рев'ю.
2. `uv run math-books verify-audio buzzer --refresh` — повторне розпізнавання
   наявних незмінених кліпів за поточною QA-політикою, без повторного TTS.
3. Новий рендер через `uv run math-books build buzzer`: старий render fingerprint
   після зміни UI не дозволяє `--skip-render`.
4. `uv run math-books verify buzzer` — повна перевірка нового експорту.

Ці дії над історичним відео не виконувалися в межах виправлень.

## Перевірки

- 213 unittest пройшли; Ruff check/format, `ty check`, `uv lock --check` і
  `git diff --check` — без помилок.
- Реальний `list --lang uk/ru/en` завершився успішно; розміри й час модифікації
  всіх 743 файлів у `videos/`, `test_videos/`, `content_reviews/` до/після
  однакові. Регресії окремо забороняють ASR, медіасубпроцеси й хешування медіа.
- Тести перевіряють `busy` з активним flock, відсутність створення lock-файла,
  збереження старого JSON при перерваному replace, очищення секретів,
  поточні/застарілі QA-квитанції, короткі змінні й одиниці, просторові умови
  та незалежність імпортів базових модулів.
- Нових викликів TTS і перегенерації історичних відео не було.
